# 重构店铺地址定位功能

## Context（背景）

当前"店家 - 我的 - 店铺信息"（`pages/merchant/shop-info/shop-info.vue`）中，店铺地址定位直接用微信原生 `uni.chooseLocation`（L210-297 `onChooseLocation`）。该方法交互不可控（无法自定义 UI / 搜索 / 拖动选点），且坐标反显依赖原生页面。

用户已确认重构方向：
1. **放弃原生 chooseLocation，自研全屏地图选点页**（uni-app `<map>` 组件）。
2. 选点页能力：**拖动地图选点 + 地址搜索**，中心准星，拖动停止后反显地址，顶部/底部确认按钮回传。
3. **逆地理编码走后端**：前端拿坐标调后端新增接口，后端调用**高德 Web Service API** 换取地址文本。key 只存后端，绝不进前端。
4. 高德 key 已由用户提供：`a69813bd913564d1c8686e93cf524799`。
5. 可同步修改 `order-backend`。

已核实：
- 后端 `context-path=/order_backend`；Result 结构 `{code, message, data}`；已有 hutool-all（HttpUtil）+ fastjson `com.alibaba.fastjson`.
- `GlobalExceptionHandler` 会把 RuntimeException 转为 `Result.error(msg)`，Service/Controller 抛异常即可，无需手写 try/catch。
- `/api/map/**` 不在 `MerchantAuthInterceptor` 的 `MERCHANT_RULES` / `LOGIN_ONLY_RULES` 中，`preHandle` 默认放行 → 新接口**无需登录**即可访问。
- 前端 `request.js` 的 `http.get` 自动携带 baseUrl + token 并解包 `data`。
- 坐标：微信 `getLocation({type:'gcj02'})` 返回 gcj02，高德同用 gcj02，**无需转换**；高德改用方式为 **"经度,纬度"（lng,lat）**，顺序千万别反。

## 后端改动（order-backend）

### 1. `src/main/resources/application.yml` 追加
```yaml
# ==================== 高德地图 Web 服务配置 ====================
amap:
  key: a69813bd913564d1c8686e93cf524799
  regeo-url: https://restapi.amap.com/v3/geocode/regeo
  search-url: https://restapi.amap.com/v3/assistant/inputtips
```

### 2. DTO（新建，风格对齐现有 dto，Lombok `@Data`）
- `com.order.dto.RegeoVO`：`province`、`city`、`district`、`formattedAddress`、`address`、`building`、`poiName`
- `com.order.dto.PoiVO`：`name`、`address`、`district`、`adcode`、`latitude`、`longitude`

### 3. Service（新建接口 + 实现）
- `com.order.service.MapService`
  - `RegeoVO regeo(double latitude, double longitude)`
  - `List<PoiVO> search(String keyword, double latitude, double longitude)`
- `com.order.service.impl.MapServiceImpl`
  - `@Value` 注入 `amap.key / regeo-url / search-url`.
  - regeo URL：`regeo-url + "?key=" + key + "&location=" + longitude + "," + latitude + "&output=JSON&extensions=base"`，`HttpUtil.get(url, 5000)`。
  - search URL：`search-url + "?key=&keywords=" + encode(keyword) + "&location=lng,lat&datatype=poi&output=JSON&citylimit=true"`（中文 keywords 必须 URL 编码）。
  - 统一判断 `"1".equals(status)` 为成功，否则抛 RuntimeException（含 infocode/info）。
  - regeo 解析 `regeocode.formatted_address`、`addressComponent.{province,city,district}`；`city` 为空时用 `province` 兜底（直辖市）。poiName 取 `regeocode.pois[0].name`。
  - search 解析 `tips[]`，`location` 按 `"lng,lat"` 拆分填经纬度。

### 4. Controller（新建）
- `com.order.controller.MapController`（`@RequestMapping("/api/map")`）
  - `GET /regeo`：`@RequestParam double latitude, longitude` → `Result.success(mapService.regeo(...))`
  - `GET /search`：`@RequestParam String keyword, double latitude, double longitude` → `Result.success(mapService.search(...))`

## 前端改动（order-frontend-app）

### 1. `src/pages.json` 注册选点页
在 shop-info 项后追加：
```json
{
  "path": "pages/merchant/map-pick/map-pick",
  "style": { "navigationBarTitleText": "选择店铺位置" }

```

### 2. `src/api/index.js` 追加封装
```js
// ==================== 地图定位 / 搜索 ====================
reverseGeocode: (params) => http.get('/api/map/regeo', params || {}),
searchPoi: (params) => http.get('/api/map/search', params || {}),
```

### 3. `src/pages/merchant/map-pick/map-pick.vue`（新页面，核心）
- 结构：顶部搜索栏 + 搜索结果列表（浮层）+ 全屏 `<map id="mapPicker">` + 中心准星（绝对定位 view）+ 底部地址反显条 + 确认按钮。
- data：`center:{latitude,longitude}`（唯一可信坐标源）、`scale:16`、`keyword`、`list`、`showResult`、`addressResult`、`addressPlaceholder`、`mapContext`、`regeoRequestSeq`、`searchTimer`、`selectedPoi`.
- `onLoad(options)`：有 `latitude/longitude` 用其作初始中心否则默认兜底 + `getLocation` 定位；`createMapContext('mapPicker')`；有初始坐标则 `refreshRegeo()`；`options.address` 作为 addressPlaceholder.
- 拖动选点：监听 `@regionchange`，`e.type==='end'` 时 `mapContext.getCenterLocation()` 取中心，写回 `center`，调 `api.reverseGeocode` 反显 `addressResult`；用递增 `regeoRequestSeq` 丢弃过期响应。
- 搜索：input `@input` 300ms 防抖调 `api.searchPoi`（以当前 center 为 location 邻近），列表项点击 `moveToLocation` + 回填 center + 直接取该项 name/address 反显，关闭列表。
- 确认 `onConfirm()`：`uni.$emit('shop-location-selected', { address, name, latitude, longitude })` + `uni.navigateBack()`；坐标取 `center`。
- `onUnload` 清理 `searchTimer`；确认时才 emit（取消/返回不 emit，保持"不选点不改"语义）。

### 4. `src/pages/merchant/shop-info/shop-info.vue`（改）
- `onLoad` 注册 `uni.$on('shop-location-selected', this.onLocationSelected)`；`onUnload` 必须 `uni.$off('shop-location-selected', this.onLocationSelected)`（传同名函数引用精确解绑）。
- 替换 `openMapChooser` 为 `uni.navigateTo` 跳 `/pages/merchant/map-pick/map-pick`，把当前 latitude/longitude（来自 `getLocation` 或已有）、已有 `address` 拼进 query；保留原有 `getLocation` 成功/失败分支、auth/deny → `openSetting` 引导、`_picking` 防重入逻辑。
- 新增 `onLocationSelected(data)`：写回 `form.latitude/longitude/address`（address 为空则保留旧值）、重建 `mapMarkers`、`markDirty()`、toast。逻辑对齐旧 chooseLocation 的 success 回调。

## 关键注意点
- 高德 `location` 参数固定 `lng,lat`，与前端 `{latitude,longitude}` 顺序相反，后端拼接务必 `longitude + "," + latitude`。
- 微信端 gcj02 一致无需转换；H5 `<map>`/getCenterLocation 支持不完整，正式定位以微信小程序为准，H5 作兜底（搜索选点仍可用）。
- 中心准星视觉中心 = 地图视野中心 = `getCenterLocation()`，无需偏移计算。
- key 只放后端配置文件，前端只显示接口返回地址，绝不明文透传 key。
